01

제품 방향과 판단 범위

iOS·Android 공통 앱으로 개발하되, 검증된 일부 교차로에서 시작하고 지원 지역을 확대합니다. 핵심은 가까운 신호등이 아니라 내가 주행 중인 도로·접근 방향에 해당하는 신호를 선택하는 것입니다.

위치·속도·방향→주행 도로 매칭→전방 교차로·신호 선택→신호·잔여시간 표시→도착 가능 여부 예측

‘통과 가능’은 안전한 통행을 보장하는 의미로 표시하지 않습니다.

API 지연, GPS 오차, 앞차와 대기행렬은 네 API만으로 해결되지 않습니다. 실제 신호와 도로 상황이 항상 우선이며, 불확실할 때는 판단을 보류합니다.

구분제품 정의
표시하는 것현재 속도 유지 시, 녹색 종료 전에 정지선에 도달할 수 있는지에 대한 참고 예측.
보장하지 않는 것실제 교차로 통과 완료, 앞차와의 충돌 방지, 안전한 진입 여부.
판단 기준실제 신호와 도로 상황이 앱보다 우선.
필수 예측 상태도달 가능 예상 / 도달 어려움 예상 / 판단 불가.

계획 수립 당시 프로젝트 폴더에는 구현 파일이 없었습니다. 기존 코드나 기술 스택을 전제로 하지 않은 신규 개발 계획입니다.

02

API 활용 전략

네 API를 처음부터 모두 연결하기보다 전국 통합 API를 우선 검증하고, 서울 API를 보완 소스로 추가합니다. 울산은 이용허락 조건을 해결한 후 연결합니다.

API활용 계획구현 전 확인 사항
① 전국 통합교차로 기본정보 및 신호색·잔여시간의 우선 데이터 소스.실제 제공 교차로, 방향 의미, 잔여시간 단위·기준시각, 호출 한도.
② 서울 신호 정보서울 지역 차량·보행·자전거·버스 등의 현재 신호 상태 조회.별도 apiKey, 교차로·방향 식별, 상태 코드.
③ 서울 잔여시간②와 결합하여 서울 지역 잔여시간 제공.단위 혼재, 두 응답의 시각 정합성.
④ 울산 C-ITS비상업적 실증 또는 별도 이용허락 확보 후 직진·좌회전 신호 연동.상업적 이용 제한, 출처 표시, 호출 한도. 최적신호연동속도·보행자 충돌 방지 등 별도 기능은 초기 범위 밖.

공식 문서에서 확인한 제약

전국 통합 API

  • 제공기관: 행정안전부 한국지역정보개발원. REST, JSON/XML, 무료, 개발·운영 자동승인.
  • 기본 경로: https://apis.data.go.kr/B551982/rti. 교차로 정보 /crsrd_map_info, 신호정보 /tl_drct_info.
  • 8방향별 직진·좌회전·유턴·보행·자전거·버스 신호의 상태와 잔여시간을 제공하지만, 전국 모든 교차로 제공을 의미하지 않습니다.
  • 개발계정 트래픽은 5,000으로 표시됩니다. 적용 기간·집계 기준은 승인 내역에서 확인합니다. 운영계정은 활용사례 등록 후 증설 신청이 가능하다고 안내되어 있습니다.
  • 실제 신호와 차이가 발생할 수 있어 참고용 사용을 권고합니다. 제공기관은 해당 데이터에 기반한 손해·사고·법적 책임을 지지 않는다고 명시합니다.

서울 API

  • 공공데이터포털에는 외부 연결형으로 등록되어 있으며, 서울 제공기관 명세는 별도 apiKey를 요구합니다.
  • 공공데이터포털에는 개발단계 자동승인, 운영단계 심의승인으로 표시됩니다. 실제 운영 조건은 서울 제공기관에서 확인합니다.
  • 잔여시간 필드명·변수 설명에는 ‘센티초’, 값 설명에는 1/10초가 함께 기재되어 있습니다. 필드명만 보고 변환하지 않습니다.
  • 서울 제공기관 페이지에는 저작자 표시 정책이 있습니다. 포털의 ‘제한 없음’ 표기만으로 출처 표시를 생략하지 않습니다.

울산 API

  • REST/JSON, 직진·좌회전 신호색 및 잔여시간(초) 제공. 실제 필드 의미는 활용가이드와 응답으로 검증합니다.
  • 출처표시·상업적 이용금지, 공공누리 제2유형입니다.
  • 상용 서비스에서는 별도 허락 없이 포함하지 않는 것을 기본값으로 둡니다. 무료 앱이라고 비상업적 이용으로 단정하지 않습니다.
  • 개발계정 트래픽은 100으로 표시됩니다. 운영 증설과 적용 기준을 확인해야 합니다.

데이터 소스를 임의로 섞지 않습니다. 같은 교차로가 여러 API에 존재하더라도 전국 API의 신호색과 서울 API의 잔여시간을 임의로 조합하지 않습니다. 교차로·접근 방향·신호 종류·기준시각이 일치하는 하나의 묶음으로 취급합니다.

03

첫 출시 범위

첫 검증 버전에 포함

  1. 위치 권한 안내 및 주행 시작·종료.
  2. 현재 속도와 이동 방향 표시.
  3. 주행 도로상의 바로 앞 교차로 자동 선택.
  4. 적용되는 차량 신호의 색상과 잔여시간 표시.
  5. 정지선까지 거리와 예상 도착시간 표시.
  6. 녹색 종료 전 도달 가능 여부 예측.
  7. 데이터 지연·GPS 불량·미지원 교차로 안내.
  8. 데이터 출처와 마지막 갱신 시각 표시.

확장 순서와 제외 범위

  1. 1차 현장 검증: 접근 방향이 명확한 직진 구간.
  2. 출시 범위 확장: 경로 안내를 결합한 직진·좌회전 신호 선택.
  3. 후속 검토: 유턴·특수 신호, 지원 지역 확대.

초기 제외: 자체 턴바이턴 내비게이션, CarPlay·Android Auto, 권장 가속 속도 기능.

“몇 km/h로 달리면 통과” 같은 가속 유도는 제공하지 않습니다.

휴대폰 GPS만으로 차로와 회전 의도를 안정적으로 알 수 없습니다. 목적지 없이 사용하는 모드는 직진 기준임을 명시하고, 분기점처럼 진행 방향이 불명확하면 예측하지 않습니다.

04

가장 중요한 기술: 내 앞의 신호 찾기

GPS에서 가장 가까운 교차로를 선택하면 반대편 차도, 고가도로 아래 교차로, 옆 도로의 신호를 잘못 보여줄 수 있습니다. 거리보다 도로 연결 관계와 접근 방향이 우선입니다.

  1. 위치·속도·이동 방향 수집

    주행 중에는 GPS 이동 방향을 우선 사용합니다. 위치 정확도·속도 정확도·측정 시각을 함께 관리합니다. 정차·저속에서는 최근 주행 이력과 도로 방향을 사용하되 확신이 없으면 판단을 보류합니다.

  2. 주행 도로에 매칭

    최근 위치 이력과 방향으로 도로 링크에 매칭합니다. 일방통행, 도로 연결 관계, 고가·지하차도 구분을 반영합니다.

  3. 도로를 따라 전방 교차로 탐색

    직선거리 대신 주행 도로를 따라가는 거리를 사용하고, 이미 지나친 교차로는 제외합니다. 인접 교차로 사이에서 선택이 반복해서 바뀌지 않도록 전환 조건을 적용합니다.

  4. 접근 방향과 신호 종류 선택

    도로 링크 → 교차로 접근로 → API 방향 코드 → 직진·좌회전 신호를 연결합니다. API의 ‘북쪽’이 북쪽으로 진행한다는 의미인지, 북측에서 진입한다는 의미인지 현장 검증합니다. 각도를 단순히 8등분해 API 방향에 대입하지 않습니다.

  5. 정지선까지 거리 계산

    교차로 중심점이 아니라 적용 신호의 정지선을 기준으로 계산합니다. 정지선 정보가 없는 교차로는 보정 데이터를 확보하기 전까지 도달 예측을 비활성화합니다.

네 API 외에 필요한 데이터

추가 데이터필요한 이유
도로 링크·노드와 연결 관계내 도로상의 다음 교차로 식별.
도로 방향·일방통행·입체교차 정보반대 차도·고가도로 오매칭 방지.
접근로별 정지선 위치도착시간 계산.

경로와 회전 정보좌회전 등 진행 의도 판단.

지도 표시 기능과 도로 그래프·정지선 데이터 제공은 별개입니다. 지도·경로 공급자의 기능 및 저장·가공 허용 범위를 확인해야 합니다. 첫 실증 구간은 대응표를 수작업으로 검증하고 이후 자동화합니다.

05

잔여시간 기반 예측 로직

기본 계산

현재 속도가 유효하고 일정하게 유지된다고 가정합니다. 속도는 m/s, 거리는 m, 시간은 초로 정규화합니다.

예상 도착시간 = 정지선까지의 도로상 거리 ÷ 현재 속도
보정 잔여시간 = 수신 잔여시간 − 기준시각부터의 경과시간

위치·속도 오차와 데이터 지연의 불확실성을 반영해 도착시간 범위와 녹색 종료시간 범위를 비교합니다. 단일 시점 계산을 확정적인 통행 지시로 사용하지 않습니다.

조건표시
현재 녹색이며, 가장 늦은 예상 도착도 가장 이른 녹색 종료보다 충분히 빠름녹색 내 도달 가능 예상
현재 녹색이며, 가장 빠른 예상 도착도 가장 늦은 녹색 종료보다 늦음이번 녹색 내 도달 어려움 예상
두 시간 범위가 겹침판단 불가 — 신호 변경 임박
현재 적색적색 표시, 이후 통과 예측 보류
현재 황색·점멸·상태 불명통과 가능 예측하지 않음
정차·GPS 불량·데이터 만료·방향 불명판단 불가

적색 잔여시간만으로 다음 녹색의 길이나 통과 가능 여부를 추정하지 않습니다. 다음 신호 순서와 지속시간이 별도로 검증되어야 합니다.

계산 예시

입력

  • 정지선까지 거리: 150m
  • 현재 속도: 36km/h = 10m/s
  • 수신 녹색 잔여시간: 24초
  • 기준시각 이후 경과: 1초
  • 예시 불확실성 여유: 3초

단순화한 비교

예상 도착: 150 ÷ 10 = 15초

비교할 잔여시간: 24 − 1 − 3 = 20초

15초 뒤 도달은 녹색 종료 전으로 예상됩니다. 앞차 감속·대기행렬은 반영되지 않습니다.

3초는 설명용 값이지 안전성이 검증된 기준이 아닙니다. 실제 기준은 제공기관별 지연 측정과 현장 비교로 정합니다. 이 예시는 범위 기반 알고리즘을 설명하기 위한 단순화입니다.

데이터 처리 불변 조건

  • 원본 생성·전송 시각, 서버 수신 시각, 앱 수신 시각을 구분합니다.
  • 같은 데이터가 반복 수신되어도 새로운 신호로 취급하지 않습니다.
  • 서울 상태와 잔여시간은 교차로·장비·메시지 시각 등 확인된 식별 기준으로 결합합니다.
  • 잔여시간 0과 값 없음을 구분합니다.
  • 카운트다운이 0에 도달했다고 다음 신호색을 임의로 생성하지 않습니다.
  • 데이터가 만료되면 기존 ‘가능 예상’을 즉시 해제합니다.
  • 신뢰할 수 있는 시간 기준을 확보할 수 없는 소스는 통과 예측에 사용하지 않습니다.

호출량은 사업성 검증 항목

1초마다 한 번 요청하면 하루 86,400회입니다. 페이지 조회와 서울의 상태·시간 분리 호출은 추가됩니다. 개발계정 한도만으로 지속적인 실시간 서비스가 가능한지 먼저 확인해야 합니다.

  • 교차로별 조회인지, 여러 교차로를 일괄 조회할 수 있는지.
  • 실제 원천 갱신 주기와 초당·일일 호출 한도.
  • 운영계정 증설 가능 범위.
  • 이용 중인 구간만 수집해도 필요한 품질을 확보할 수 있는지.

앱의 카운트다운을 매초 갱신하는 것과 원천 API를 매초 호출하는 것은 다릅니다. 화면에서 시간을 줄여 표시하는 것만으로 데이터의 최신성이 확보되지는 않습니다.

표시와 상호작용 원칙

  • 주행 화면 안에서는 스크롤·탭 전환 없이 핵심 신호와 결과를 볼 수 있도록 설계합니다. 문서의 설명·대안 카드는 실제 주행 화면에 함께 표시하지 않습니다.
  • 신호색·숫자·결과의 위치를 고정하고, 높은 명암 대비와 문자·도형을 함께 사용합니다. 그래프를 읽지 않아도 기본 결과를 알 수 있어야 합니다.
  • 카운트다운은 정수로 표시하고 장식 애니메이션·점멸·급격한 축 확대를 피합니다. 그래프의 두 막대는 언제나 같은 시간축을 사용합니다.
  • 신호 변경 임박·데이터 만료 시 ‘가능 예상’을 즉시 해제합니다. 적색·황색·점멸에는 현재 신호 상태를 우선하고 통과 가능 예측을 하지 않습니다.
  • 주행 중 복잡한 설정·교차로 선택 조작을 요구하지 않습니다. ‘가속하세요’, ‘지금 통과하세요’, ‘출발하세요’ 안내를 하지 않습니다.
  • 미지원 구간에는 ‘전방 신호 정보 없음’을 표시합니다. 다른 도로의 지원 신호로 대체하지 않습니다.
  • 지도와 상세 진단 정보는 보조 화면으로 분리합니다. 큰 글꼴에서 공간이 부족하면 그래프보다 신호와 결과를 우선합니다.
  • 실차 가독성은 아직 검증되지 않았습니다. 거치 거리·주야간·큰 글꼴 조건에서 짧은 시선으로 상태를 구분할 수 있는지 동승자 또는 정차 환경에서 검증합니다.

첫 버전은 앱을 켜고 주행 시작을 누른 전경 주행 모드로 제한합니다. 백그라운드 위치 추적은 배터리·개인정보·스토어 심사 요구사항을 검토한 뒤 추가합니다.

08

개발 일정과 완료 기준

모바일 1명·서버/공간정보 1명, API 승인 및 지도 데이터 확보를 전제로 한 계획상 추정입니다. 승인 대기와 별도 데이터 계약 기간은 제외합니다.

단계예상 기간작업완료 기준
1. 데이터 타당성 검증1~2주키 발급, 실제 응답 수집, 커버리지·단위·방향·지연·쿼터 확인.실증 교차로와 예측에 사용할 수 있는 데이터 소스 확정.
2. 공간 데이터 구축2~3주도로·접근로·정지선 매핑, 전방 교차로 선택.선정 구간에서 반대편·인접 도로·통과 후 전환 검증.
3. 서버·앱 구현3~4주API 수집·정규화·캐시, 위치·지도·신호 UI.두 플랫폼 실기기에서 실제 신호 데이터 표시.
4. 예측 엔진 구현1~2주시간 보정, 도착시간 범위, 판단 보류 조건.경계·누락·지연·정차 시나리오 검증.
5. 현장 검증·배포 준비2~3주실제 신호 비교, 배터리·네트워크 확인, 약관·심사 준비.검증 구간 한정 베타 배포.

합계 약 9~14주를 초기 계획으로 잡되, 1단계 결과로 다시 산정합니다. 호출량이나 지연이 요구 품질을 충족하지 못하면 화면 개발을 계속하기 전에 데이터 제공 방식부터 조정합니다.

반드시 검증할 시나리오

  • 같은 교차로에 네 방향으로 접근.
  • 직진·좌회전 신호가 서로 다른 경우.
  • 고가도로와 하부도로, 평행도로.
  • 정차 후 출발, 회전 직후, 교차로 통과 후 다음 교차로 선택.
  • GPS 점프·정확도 저하·위치 권한 거부.
  • 서울 상태·잔여시간 응답의 시각 불일치.
  • 응답 반복·역순 도착·누락·네트워크 단절.
  • 감응식 제어 등으로 잔여시간이 변경되는 경우.
  • 녹색 종료 경계에서 ‘가능 예상’이 잘못 남는 경우.

출시 품질 판단

전체 정확도 하나가 아니라 잘못된 신호 선택률, 낙관적 오판율, 판단 불가 비율, 데이터 나이의 p95·p99를 나누어 봅니다. 수치 기준은 실측 후 정하며, 현 단계에서 검증되지 않은 정확도를 약속하지 않습니다.

검증 중 잘못된 방향에 ‘가능 예상’이 나온 교차로는 원인 해결 전 지원 대상에서 제외합니다. 현장 비교는 동승자 기록이나 고정 촬영 등으로 진행하고, 운전자가 앱을 조작하며 검증하지 않습니다.

첫 실행 목표

전국 통합 API 기반으로 검증 가능한 10~20개 교차로를 선정합니다. 직진 접근에서 ‘올바른 신호 선택 → 최신성 검증 → 정지선 도착 예측’을 먼저 입증합니다.

그다음 서울 API와 회전 경로를 결합하고, 울산은 이용허락 조건을 해결한 뒤 추가합니다. 이 앱의 성패는 화면보다 접근 방향 매핑, 정지선 데이터, 원천 데이터 지연에 달려 있습니다.

근거와 미검증 사항

공식 공개 문서를 확인해 작성한 계획입니다. 인증키를 사용한 실제 API 응답·제공 교차로·현장 지연은 아직 검증하지 않았으며, 1단계의 선행 조건입니다. 기술 스택·일정·실증 규모는 권장 계획이지 구현 완료 또는 성능 검증 결과가 아닙니다.

  1. 전국 통합 교통안전 신호등 실시간 정보 — 공공데이터포털
  2. 서울특별시 V2X 신호제어기 신호 정보 — 공공데이터포털
  3. 서울특별시 V2X 신호제어기 잔여시간 정보 — 공공데이터포털
  4. 서울 제공기관 잔여시간 상세 명세 — 서울교통빅데이터플랫폼
